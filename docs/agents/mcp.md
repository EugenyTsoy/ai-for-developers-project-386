# MCP в OpenCode

В корневом `opencode.json` настроен один MCP-сервер: официальный
[Render MCP](https://render.com/docs/mcp-server). Конфигурация использует формат
[OpenCode V2](https://opencode.ai/v2/docs/mcp-servers) (`mcp.servers`).
Для запуска самого CallBooking MCP и ключ Render не нужны.

## Настройка

1. Установите OpenCode V2. Создайте личный API-ключ в
   [Render Account Settings](https://dashboard.render.com/u/settings?add-api-key).
2. Передайте ключ в переменной окружения `RENDER_API_KEY` процессу OpenCode.
   Например, в Bash ввод без отображения и сохранения ключа в истории команд:

   ```bash
   read -r -s -p 'Render API key: ' RENDER_API_KEY
   export RENDER_API_KEY
   ```

   В Windows задайте переменную окружения для процесса через свой менеджер
   секретов или настройки пользовательских переменных, затем откройте новый терминал.
   Уже запущенный OpenCode нужно перезапустить, чтобы он унаследовал переменную.
3. Из корня репозитория выполните `opencode mcp list`: ожидается
   `render connected`. Без переменной подставляется пустая строка, аутентификация
   Render не сработает. Не публикуйте диагностический вывод с заголовками авторизации.
4. Перед запросами к ресурсам попросите агента перечислить workspaces и подтвердите
   нужный workspace. Начните с чтения списка сервисов, без изменения инфраструктуры.

Не записывайте ключ в `opencode.json`, документацию или коммиты. OpenCode читает
переменную окружения процесса; `.env` автоматически этой настройкой не загружается.
Глобальную конфигурацию менять или копировать в репозиторий не требуется.
Проектная запись `render` заменяет одноимённую глобальную запись целиком;
остальные глобальные MCP-серверы сохраняются.

Локальный `vs-mcp` (`localhost:3001`, Visual Studio) намеренно не включён:
он зависит от окружения разработчика и не нужен для работы с Render.

**Важно:** Render MCP умеет не только читать данные, но и запускать deploy,
создавать ресурсы и менять переменные сервиса. Не разрешайте такие операции без
отдельного подтверждения владельца; проверка подключения не требует redeploy.
