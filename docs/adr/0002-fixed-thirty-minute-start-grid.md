# ADR-0002: фиксированный интервал стартов, переменная длительность

**Статус:** принято, 2026-10-16, по запросу владельца после Submission Audit.

Сетка с шагом длительности EventType давала разные допустимые старты для разных типов и не соответствовала согласованному 30-минутному интервалу начал. Вместо неё используем `start(k) = openInstant + k × 30 минут`, `end(k) = start(k) + durationMinutes`: длительность остаётся положительным целым числом, а кандидат целиком входит в рабочее окно. Якорь — открытие окна, не полночь, не округлённые часы и не текущее время; обе формулы работают на UTC timeline, включая DST.

Перекрывающиеся кандидаты допустимы, сохранённые Booking — нет: атомарная проверка пересечений остаётся общей для всех типов. Например, 45-минутная запись 09:00–09:45 блокирует кандидат 09:30, но не 10:00; конец записи не создаёт новый старт 09:45. Off-grid и неполное вхождение остаются HTTP 400, канонический, но уже недоступный выбор — HTTP 409. Маршруты и DTO не меняются.

Гость сначала выбирает тип, затем дату в timezone календаря, затем время. Дата группирует серверные слоты на клиенте, не добавляет API-операцию и не резервирует слот. Смена даты или типа сбрасывает выбранный слот; после 409 доступность перечитывается без автоматического повтора POST.

Альтернатива — сохранить шаг длительности — отвергнута. Не вводятся ограничение длительности 30 минутами, обратная совместимость, миграции или переходный режим. Это решение заменяет правило сетки редакции 1 спецификации; остальные правила времени, DST и атомарности сохраняются.
