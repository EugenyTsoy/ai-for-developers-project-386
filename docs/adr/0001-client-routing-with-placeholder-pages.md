# Клиентская маршрутизация с техническими заглушками

Для текущего шага, ограниченного главной страницей Calendar, выбран React Router с BrowserRouter и обычными URL: `/` для главной, `/booking` для записи и `/events` для раздела «Предстоящие события». Обычные ссылки без клиентского маршрутизатора отклонены: переход должен давать отдельный результат, а не повторно показывать главную через fallback Vite. Общая шапка отображается на всех трёх страницах; логотип ведёт на `/`, обе ссылки «Записаться» — на `/booking`, ссылка «Предстоящие события» — на `/events`.

Чтобы работающая навигация не расширяла границы шага до реализации будущих функций, `/booking` и `/events` содержат только соответствующий заголовок («Запись на звонок» или «Предстоящие события») и текст «Раздел пока не реализован». Формы, календарь, карточки, данные и бизнес-логика этих разделов не входят в текущую реализацию; возврат на главную доступен через логотип в общей шапке. Серверный SPA fallback для прямого открытия вложенных адресов остаётся будущим инфраструктурным требованием и сейчас отдельно не реализуется.
